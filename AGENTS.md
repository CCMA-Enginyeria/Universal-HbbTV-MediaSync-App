# Universal HbbTV MediaSync App — Agent Notes

Native **Kotlin/Jetpack Compose (Android)** and **Swift/SwiftUI (iOS)** apps for DIAL/HbbTV discovery and companion-screen media sync (private listening, DVB-CSS). The former React Native app was retired; it is only in the Git history (last on `main` at `1a3f4e9`). The native apps keep its package/bundle ids and import its stored sync mode, so they update the published app in place.

This is a **white-label / forkable** app: every brand-specific value (name, identifiers, version, colors, splash, default language, App2App channel) lives in `src/brand/brand.config.js`. `native/tools/export-brand.cjs` turns it, plus the shared strings and theme, into generated resources for both apps. A fork should normally only edit that file.

## Critical Setup Gotchas

- **Generated resources are not versioned and must not be edited by hand**: Android brand resources are generated by the Gradle build; iOS `native/ios/App/Generated/` and `MediaSync.xcodeproj` by `native/ios/App/generate.sh` (XcodeGen).
- **Gradle 8.14 needs JDK 17 or 21** to run (Android Studio's bundled JDK 25 fails with an unhelpful version error); the build uses a Java 17 toolchain.
- **Release signing**: `MEDIASYNC_KEYSTORE`, `MEDIASYNC_KEYSTORE_PASSWORD`, `MEDIASYNC_KEY_ALIAS`, `MEDIASYNC_KEY_PASSWORD`. Without them `assembleRelease`/`bundleRelease` succeed **unsigned**.
- **`versionCode`/build number** derive from `version` in the brand config (`1.4.1` → `10401`); override with `MEDIASYNC_VERSION_CODE`.
- **Android `minSdk` is 24** (same as the RN app) thanks to core library desugaring (`java.time` in `:core`); guard API 26+ calls or use compat classes.
- **iOS physical-device multicast needs Apple's approved `com.apple.developer.networking.multicast` entitlement** (only the store bundle id has it). Debug `.dev` builds without it: build with `CODE_SIGN_ENTITLEMENTS=` and launch with `MEDIASYNC_SSDP_DESTINATION=<TV IP>` (Debug-only unicast M-SEARCH). The simulator works without it.
- **Shared contract**: `native/fixtures/protocol` is consumed by both cores. A behavior change there must be implemented in Kotlin **and** Swift.

## Commands

| Task | Command |
|------|---------|
| Reference vectors / brand check | `node native/tools/sync-vectors.cjs --check` · `node native/tools/export-brand.cjs --check` |
| Android tests, build, lint | `cd native/android && ./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug` |
| Android end to end vs. emulator | start `tools/tv-emulator`, then `./gradlew :core:test -Pmediasync.emulator=<IP>` |
| Android signed release | set `MEDIASYNC_*`, then `./gradlew :app:bundleRelease` |
| iOS core tests | `swift test --package-path native/ios` |
| iOS app | `sh native/ios/App/generate.sh`, then `xcodebuild -project native/ios/App/MediaSync.xcodeproj -scheme MediaSync -destination 'platform=iOS Simulator,name=<installed iPhone>' CODE_SIGNING_ALLOWED=NO test` |
| TV emulator | `cd tools/tv-emulator && npm ci && EMU_IP=<LAN IP> node index.js` |

See `native/README.md` for details, contracts and known gaps.

## Architecture & Boundaries

- **`native/android/core`** — pure Kotlin/JVM core: DIAL/SSDP discovery, DVB-CSS CII/WC/TS, App2App, session and probe state machines, playback corrector, MPD/HLS/TTML/VTT parsers, companion protocol. No Android APIs, no I/O except through the injected `Transport`.
- **`native/android/app`** — Compose UI, Media3 player, `SyncService` foreground service, OkHttp/UDP transport bound to the LAN, Custom Tabs/WebView companion.
- **`native/ios/Sources/MediaSyncCore`** — Swift port of the core (same fixtures, Swift Package).
- **`native/ios/App`** — SwiftUI app, AVPlayer, WKWebView companion; DASH plays through the brand's sync web player (`syncWebPlayerUrl`).
- **Cores are serial state machines**: every socket and timer goes through `Transport` with a unique token, so events from replaced connections are ignored. Call them on the owner's thread (Android main looper, iOS main queue).
- **Shared inputs** (do not delete): `src/brand/brand.config.js`, `src/i18n/translations.js`, `src/theme.js`, `src/data/*.json`, `assets/` (brand images), `native/i18n/native-strings.json`.
- **`www/hbbtv_examples/sync_webplayer/SyncController.js`** — behavioral reference for the sync controller; `sync-vectors.cjs` pins the native ports to it.
- **`tools/tv-emulator/`** — Node.js DVB-CSS/HbbTV TV emulator (SSDP/DIAL, CSS-CII/WC/TS, App2App) with its own `package.json`. If discovery stops working, restart it first: its SSDP socket can lose the multicast membership.
- **`www/`** — landing page and IBC demonstrations (GitHub Pages), HbbTV examples, `hbbtv-compat` library for broadcasters. **`store/`** — store metadata. **`docs/prds/`** — native requirements, parity matrix, threat model.

## CI / Deployment

- **`native-core.yml`** — on push to `main`/`native-apps`, pull requests and manual dispatch: reference vectors, brand check, Android tests/build/lint (incl. emulator end to end), Swift tests, iOS simulator tests and unsigned archive.
- **`build-android.yml`** — on `v*` tags (tag must equal `v` + brand `version`) or manual dispatch: signed release APK + AAB of the native app, signatures verified, attached to the GitHub release. Secrets: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` (the Play upload key).
- **`build-ios.yml`** — on `v*` tags (uploads to App Store Connect/TestFlight) or manual dispatch (upload optional, build number override): signed App Store IPA of the native app with manual signing via the untracked `native/ios/App/Config/Signing.xcconfig`; checks the profile carries the multicast entitlement. Secrets: `IOS_DIST_CERT_P12_BASE64`, `IOS_DIST_CERT_PASSWORD`, `IOS_PROVISIONING_PROFILE_BASE64`, `APPSTORE_API_KEY_ID`, `APPSTORE_API_ISSUER_ID`, `APPSTORE_API_PRIVATE_KEY`. Submitting for review stays manual.
- **`publish-landing-page.yml`** — deploys `www/landing` and the IBC demonstrations to GitHub Pages.

## Code Style

> **Rule: all source code, identifiers, comments, KDoc/doc comments and log messages MUST be written in English.**
> User-facing UI strings are the only exception — they are localized (see below).

- Match the surrounding style of the file you edit; no formatter is enforced.
- **Kotlin**: 4-space indentation, `camelCase` members, `PascalCase` types, `UPPER_SNAKE_CASE` constants; KDoc `/** ... */` on classes and non-trivial functions explaining *why*.
- **Swift**: 4-space indentation, Swift API naming; `///` or `/** */` doc comments explaining *why*.
- **Tests**: Kotlin in `native/android/core/src/test` and `native/android/app/src/test`; Swift in `native/ios/Tests` and `native/ios/App/Tests`. New protocol behavior gets a shared fixture case when it applies to both platforms.
- **Diagnostics**: structured, no payloads or URLs (`Diagnostics.log(area, event, fields)`).

## Internationalization (i18n)

- Supported UI languages: Catalan (`ca`), Spanish (`es`), Basque (`eu`), English (`en`), German (`de`), Italian (`it`), French (`fr`); default/fallback is brand-configurable (`defaultLanguage`, currently `en`).
- Shared strings live in `src/i18n/translations.js`; strings only the native apps use live in `native/i18n/native-strings.json`. `export-brand.cjs --check` fails on missing keys or inconsistent placeholders in any language.
- Never hardcode user-facing text in Kotlin/Swift; add keys in all 7 languages.
